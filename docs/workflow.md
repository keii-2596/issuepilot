# IssuePilot 工作流说明

IssuePilot 把开源贡献拆成互不混淆的阶段：发现、深度判断、本地准备、人工审核、发布、PR 跟进和归档。一次扫描找到很多候选，并不等于这些 Issue 都能安全地产生代码修改。

## 状态如何理解

| 状态 | 含义 | 是否有待审核 diff |
| --- | --- | --- |
| `discovered` | 通过 Stars、语言、领域、时间、标签和空闲状态筛选 | 不一定 |
| `prepared` | AI 已理解仓库并留下通过安全策略的本地修改 | 有 |
| `needs_human` | 需要维护者决策、真实账号/硬件、视觉验收或其他人工证据 | 通常没有 |
| `skipped` / `blocked` | 已有人处理、Issue 过时、策略阻止或环境不满足 | 没有 |
| `error` | GitHub、克隆、工具或运行过程失败 | 不确定，需检查工作区 |
| `published` | 已在明确授权后创建 PR | PR 中有 |
| `merged` / `closed` | 上游已结束处理 | 进入归档判断 |

`discover` 会返回当前批次候选；`autopilot` 会从持久化的下一个仓库批次重新发现并尝试，因此它不会自动消费刚刚打印的那一份列表。若希望处理指定候选，应对每个 URL 运行 `issuepilot run --issue URL`。

## 每日流程

1. 读取本地 manifest、候选档案、领域偏好、清理记录和 PR 去重状态。
2. 优先检查已发布 PR：原 Issue、全部新增讨论、Review、行内评论、CI、冲突、Draft/Ready、合并或关闭状态。
3. 把新增英文讨论逐条翻译到对应 `ISSUEPILOT_REVIEW.zh-CN.md`。
4. 对明确且仍在原范围内的维护者请求，只在本地准备修改并运行测试；展示 exact diff 后等待新的推送授权。
5. 沿用保存的 Stars、语言、领域、Issue 年龄及排序条件继续发现候选。
6. 深度判断候选是否真的可实现、可验证且没有他人正在处理，再为最多若干条创建本地 workspace。
7. 对已合并、已关闭且没有剩余工作的 workspace，写入最终说明并移动到可恢复归档；不永久删除。

## 为什么“筛到了”仍可能没有新修改

候选筛选解决的是“值得进一步看吗”，本地准备解决的是“现在能否负责任地修改并验证”。常见停止原因包括：

- Issue 是合作讨论或开放式功能方向，没有明确接口和验收标准；
- 需要真实 GCS、Snowflake、GPU 或其他外部账号/硬件验证；
- 需要在托管文档、移动浏览器或生产主题中做视觉/集成验收；
- 目标行为已经存在，只缺少真实环境证据；
- 克隆或 GitHub API 临时失败；
- 深度检查发现开放 PR、近期认领、关联提交或已修复证据。

因此汇报必须分开列出“发现数、尝试数、准备成功数、需要人工数、跳过数和错误数”，不能把“准备成功数为 0”写成“没有发现候选”。网络错误只影响明确标记为 `error` 的条目。

## 可复用的 Codex 定时任务提示

下面是一个精简模板。实际筛选条件保存在本地，不应把 token 写进任务提示：

```text
使用最新安装的 IssuePilot 执行每日开源贡献准备与已发布 PR 跟进。

先检查本地 published/pushed/committed manifest 对应的 PR 和原 Issue，读取新增讨论、Review、行内评论、CI、冲突及合并状态；用本地 pr-monitor.json 去重。新增英文讨论逐条翻译进对应中文审核说明。明确、同范围的维护者修改请求可以在本地实现并测试，但不得自动评论或 push，先汇报 exact diff 等待授权。

随后沿用保存的领域和筛选条件发现候选，分别汇报发现、尝试、prepared、needs_human、skipped/blocked 和 error 数量。只为边界明确且可验证的 Issue 准备最多 5 个本地修改，不 commit、不 push、不创建 PR。已合并或确认过时且无剩余工作的 workspace 按可恢复归档流程处理。
```

## 数据与安全边界

- `.oss-agent/candidate-archive.json` 保存候选和扫描摘要；`.oss-agent/pr-monitor.json` 保存 PR 去重状态；`.oss-agent/cleanup-ledger.jsonl` 保存归档证据。
- `.env`、token、工作区、候选档案和监控状态均保持本地，不进入项目仓库。
- 发现、分析和本地修改不授权发布；首次 PR 和后续 revision 的 push 都需要当前对话中的明确授权。
- 定时任务不自动评论、review、转 Ready、合并、关闭、打标签或操作 CLA。
